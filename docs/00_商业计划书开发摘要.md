# StudentRiskGuard 商业计划书开发摘要

> 本文是商业计划书面向开发的摘要，用于让 Codex 快速理解产品边界和 MVP 决策。原始商业计划书仍以根目录 `StudentRiskGuard商业计划书.docx` 为准；若两者冲突，先按本文的 MVP 决议执行，并提交团队确认。

## 1. 项目基本信息

- 项目名称：StudentRiskGuard
- 中文名称：大学生负债压力自检与理性消费科普 Agent
- 参赛赛事：MINMAX AI Agent 黑客松
- 团队构成：计算机方向 1 人 + 经济统计方向 1 人
- MVP 目标：做出可通过公开链接打开、匿名试用、完成完整 Agent 工具调用链路的网页作品
- 核心链路：用户输入 → Agent 理解并调用工具 → 确定性计算 → 大模型解释 → 输出风险报告

## 2. 产品定位

StudentRiskGuard 是面向在校大学生的金融教育与负债压力自查工具，不是信贷风控、授信、放款或借贷推荐系统。

产品帮助学生：

1. 汇总多笔小额分期，看到叠加后的月供压力。
2. 理解名义利率与真实年化 IRR 的差异。
3. 预判未来 12 个月现金流结余。
4. 模拟新增一笔分期后的变化。
5. 获得通俗的风险来源解释和理性消费科普。

## 3. MVP 用户与输入

核心用户：国内全日制在校本科生、研究生。

MVP 输入：

- 每月稳定可支配生活费，定义为扣除住宿、餐饮等必要支出后的金额。
- 每月兼职收入。
- 多笔分期：名称、剩余本金、月供、剩余期数、名义年利率。

MVP 不采集：

- 姓名、学号、手机号、身份证、银行卡。
- 征信报告、真实账单原文、平台账号。
- 借款申请、授信、放款相关数据。

## 4. 合规硬约束

以下约束不可被后续需求覆盖：

1. 不接入、不采集、不上传征信数据。
2. 不评估贷款能否通过，不生成额度、通过率或放款结论。
3. 不推荐任何借贷、分期或先买后付产品。
4. 不提供授信、放款、催收或借贷导流功能。
5. MVP 不做账号体系和持久化个人金融明细存储。
6. 比赛演示、测试和模型校准全部使用合成脱敏数据。
7. 所有风险分数、IRR 和现金流由确定性代码计算，LLM 不参与算数。
8. 所有主要页面固定展示“仅作金融教育与自查参考”的边界声明。

## 5. MVP 产品形态

- 主入口：Streamlit 网页，打开链接即可使用。
- 匿名会话：不设置手机号、学号或密码登录。
- 主演示路径：载入合成样本或填写表单 → 点击开始自检 → Agent 调用工具 → 查看报告。
- 结果内容：风险等级、压力分、月供收入比、逐笔 IRR、风险贡献、12 个月结余、智能解读。
- 演示样例：内置低风险、关注、中风险、高风险四组合成样本。
- 降级策略：模型超时或工具调用失败时，仍展示确定性计算结果和模板解释。

## 6. 推荐的 Agent 实现理解

MVP 不使用复杂的多 Agent 框架。采用“确定性 Agent 状态机 + DeepSeek Function Calling”：

1. 表单输入先进入匿名会话，服务端在内存中保存 `AssessmentRequest`。
2. 大模型只拿到 `session_id`，不接收原始财务明细。
3. 大模型调用 `run_risk_assessment(session_id)` 工具。
4. 工具在服务端读取会话数据，执行统计计算并返回结构化结果。
5. 大模型只基于工具结果生成解释。
6. 输出经过 Schema、数值一致性和内容安全检查后返回前端。

这样既能展示真实的 Agent 工具调用，又满足“计算与解释分离”和隐私最小化。

## 7. 初赛必须完成的最小闭环

- [ ] 公开链接可打开。
- [ ] 匿名表单可录入收入和至少 1 笔分期。
- [ ] 4 组内置样本可一键载入。
- [ ] 服务端完成指标、IRR、评分和 12 个月现金流计算。
- [ ] Agent 至少真实调用一次 `run_risk_assessment` 工具。
- [ ] DeepSeek 基于工具结果输出结构化解释。
- [ ] 页面展示确定性结果和智能解释。
- [ ] 模型故障时可降级展示模板解释。
- [ ] 不写入个人明细，不出现借贷推荐或授信结论。

## 8. MVP 不做

- 用户注册、密码、手机号验证。
- 真实账单上传或征信接入。
- 复杂 RAG、知识库、向量数据库。
- 多 Agent 框架、LangChain/CrewAI 等重型编排。
- 决赛阶段的 CSV 清洗、蒙特卡洛、历史会话和报告导出。
- 任何借贷产品推荐、额度预测和审批判断。
