# StudentRiskGuard 模块化分工与排期表

- 文档版本：MVP-PLAN-1.2
- 使用方式：每完成一个模块，将对应复选框改为 `[x]`，并在 `docs/03_任务清单.csv` 或 `docs/09_模块任务清单.csv` 更新状态。
- 执行原则：一次只让 Codex 执行一个模块，模块验收通过后才进入下一个关键模块。
- 排期方式：D1-D10，按实际启动日顺延。

## 1. 模块执行顺序

```text
M0 启动与契约冻结
 ├─> M1 工程骨架与数据模型
 └─> M2 统计计算内核
        └─> M3 会话、工具与 API
              └─> M4 Agent 工具调用链
                    └─> M5 页面闭环与情景模拟
                          └─> M6 安全、隐私与降级
                                └─> M7 公网部署与端到端验收
                                      └─> M8 Demo 与冻结提交
                                            └─> M9 自然语言录入（P1，可选）
```

关键路径：`M0 ->（M1 与 M2 都完成）-> M3 -> M4 -> M5 -> M6 -> M7 -> M8`。

### 3.5 重要说明

- M2 是统计同学的主战场，计算机同学此时完成 M1，不抢写计算公式。
- M3 开始由计算机同学封装统计函数，统计同学只做字段和边界复核。
- M4 不通过，不能进入 M5；M5 不通过，不能进入 M6。
- M6 不通过，不能部署为初赛提交版本。
- M7 完成即达到“可提交 Agent”门槛；M8 只做打包和冻结。

## 3.6 统计问卷专项并行轨道

### 3.6.0 问卷不是所有任务的全局前置条件

- M0 可以立即开始，不需要等问卷最终定稿；只需在 M0 验收前完成‘问卷题目与模型字段’的覆盖核对。问卷措辞和选项可以继续迭代，但新增或删除模型字段必须同步修改契约。
- S1-S5 与 M1-M6 并行，不需要等全部问卷回收后才开始写代码。
- M2 先用 `contracts/scorecard.example.json` 初版参数开发。
- M5 和 M6 可以在初版参数上开发页面和安全逻辑。
- M7 公网部署前必须完成 S4/S5；如果样本不足，则保留初版参数并明确说明，不得声称已完成校准。
- 因此：**问卷不阻塞 M1-M6，但阻塞最终参数冻结和 M7 提交口径。**

| 模块 | 是否必须等问卷全部完成 | 说明 |
|---|---|---|
| M0 | 只需字段映射核对 | 不需要等问卷定稿或答卷回收 |
| M1 | 否 | 可先做工程骨架和模型 |
| M2 | 否 | 先用初版配置，后续替换参数 |
| M3 | 否 | 工具和 API 与参数值无关 |
| M4 | 否 | Agent 调用和解释逻辑可先开发 |
| M5 | 否 | 页面先用初版参数开发 |
| M6 | 否 | 安全逻辑不依赖具体阈值 |
| M7 | 是，需 S4/S5 或明确保留初版参数 | 公网提交前冻结口径 |
| M8 | 否 | 只打包和冻结 |


问卷由经济统计同学主责，与 M1-M3 并行，不阻塞公式代码开发；但必须在 D7 前（M7 部署前）完成参数校准或明确保留初版参数。

| 编号 | 时间 | 任务 | 负责人 | 依赖 | 交付物 |
|---|---|---|---|---|---|
| S0 | D0-D1 | 设计问卷、3-5 人预测试、字段对齐 | 经济统计 | 无 | 问卷题目、跳转逻辑、预测试记录 |
| S1 | D1 | 正式匿名发放 | 经济统计 | S0 | 问卷链接/二维码 |
| S2 | D1-D4 | 回收答卷，目标至少 80 份有效样本 | 经济统计 | S1 | 匿名原始答卷与回收记录 |
| S3 | D4-D5 | 数据清洗、描述统计和 EDA | 经济统计 | S2 | 清洗规则、汇总数据、图表 |
| S4 | D5-D6 | 校准权重、分档和风险阈值 | 经济统计，计算机复核配置 | S3 | 校准版评分卡与参数说明 |
| S5 | D7 | 冻结参数版本并写入报告 | 经济统计 | S4 | 冻结配置、样本局限说明、版本号 |

### 3.6.1 问卷与模块的关系

- M0：确认问卷字段与模型字段一致。
- M1/M2：计算机和统计继续开发，不等问卷完成。
- M3/M4：问卷可继续回收，不影响工具和 Agent 开发。
- M5/M6：S3/S4 完成，用校准参数替换初版配置。
- M7：S5 完成，参数冻结后才能公网提交。
- M8：只解释和展示，不再调参数。

### 3.6.2 规则

- 问卷只用于汇总分析，不作为个体用户输入。
- 原始答卷不进入应用数据库、日志、前端或演示仓库。
- 如果样本量不足，保留初版参数，并在报告中写明限制。
- 问卷回收期间，统计同学仍须完成 M2 的核心计算函数。

## 7. 模块完成规则

一个模块只有同时满足以下条件才能打钩：

- [ ] 模块涉及的 T 任务全部完成。
- [ ] 代码或文档文件存在。
- [ ] 验收命令已执行。
- [ ] 测试通过或手工验证证据已记录。
- [ ] 没有新增征信、授信、放款或借贷推荐。
- [ ] 没有把完整的原始财务明细或完整聊天历史发送给 LLM；仅允许当前轮必要文本进入抽取、科普或情景模型。
- [ ] 已在 `docs/09_模块任务清单.csv` 更新状态。

## 8. 任务分配规则

- 每次只让 Codex 执行一个模块。
- Codex 开始前必须声明模块 ID、任务 ID、写入范围和依赖状态。
- Codex 不得跨模块重写文件。
- 模块之间需要修改共享契约时，先停止并请双方确认。
- 统计公式由经济统计方向负责；计算机方向只做接口封装。
- 页面与 Agent 输出由双方共同验收。
