# StudentRiskGuard MVP 接口与数据契约

- 版本：M2-CONTRACT-2026.11.04
- 状态：最终版
- 原则：接口契约先于实现；字段变更必须同步更新 JSON Schema、测试和示例

## 1. 数据流

```text
AssessmentRequest
  -> SessionStore
  -> Agent tool call: run_risk_assessment(session_id)
  -> AssessmentResult
  -> explanation generation
  -> AgentResponse
  -> Streamlit 页面
```

原始输入不直接发送给报告解释模型。自然语言抽取、科普和情景模型只接收当前轮必要文本；报告模型只接收 `session_id` 和结构化 `AssessmentResult`。工具在服务端读取完整会话数据并执行确定性计算。

## 2. 字段命名

统一使用 snake_case。

金额单位：人民币元。

时间单位：月、年。

利率字段统一使用小数：12% 写作 `0.12`。

## 3. AssessmentRequest

```json
{
  "session_id": "anon_20261101_a1b2c3",
  "income": {
    "monthly_disposable_allowance": 2200,
    "monthly_part_time_income": 800
  },
  "debts": [
    {
      "id": "d1",
      "label": "购物分期",
      "remaining_principal": 4800,
      "monthly_payment": 520,
      "remaining_periods": 10,
      "nominal_apr": 0.12
    }
  ],
  "behavior": {
    "borrow_to_repay": false,
    "strict_overdue_count": 0,
    "insufficient_months_last_3": 0,
    "income_drop_30_cannot_cover": false,
    "financial_cognition_score": 4
  },
  "forecast_months": 12
}
```

### 3.1 字段规则

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `session_id` | string | 是 | 1-64 位，字母/数字/下划线/短横线，不得包含身份信息 |
| `monthly_disposable_allowance` | number | 条件必填 | >= 0；与兼职收入合计必须 > 0 |
| `monthly_part_time_income` | number | 条件必填 | >= 0；允许为 0 |
| `debts` | array | 是 | 0-20 笔，允许无负债 |
| `debts[].id` | string | 是 | 会话内唯一，不得映射真实账户 |
| `debts[].label` | string | 是 | 1-30 字，仅作分类展示 |
| `debts[].remaining_principal` | number | 是 | > 0，建议上限 1,000,000 |
| `debts[].monthly_payment` | number | 是 | > 0，建议上限 100,000 |
| `debts[].remaining_periods` | integer | 是 | 1-120 |
| `debts[].nominal_apr` | number/null | 否 | 0-1；未知时传 `null`，仅作参考，不能替代 IRR |
| `savings_balance` | number | 否 | >=0，默认0；只参与现金流缓冲，不计入收入 |
| `recurring_subscriptions[]` | array | 否 | 持续订阅月费；进入固定支出和 DTI，不属于负债 |
| `behavior.borrow_to_repay` | boolean | 否 | 是否曾以贷养贷；触发行为与韧性规则 |
| `behavior.strict_overdue_count` | integer | 否 | 过去12个月逾期次数；>=2触发严格逾期规则 |
| `behavior.insufficient_months_last_3` | integer | 否 | 过去3个月资金不足月份数，0-3 |
| `behavior.income_drop_30_cannot_cover` | boolean | 否 | 收入下降30%时是否无法覆盖支出和当前还款 |
| `behavior.financial_cognition_score` | number/null | 否 | 1-5分量表；<=3触发认知薄弱规则 |
| `forecast_months` | integer | 否 | 1-36，默认 12 |

### 3.2 禁止字段

不得接收或存储：

- 姓名、学号、手机号、身份证号、银行卡号。
- 征信报告、真实账单原文、平台账号、密码。
- 任何授信、放款、额度或审批字段。

### 4.1 结果约束

- `metrics.income_total = monthly_disposable_allowance + monthly_part_time_income`。
- `monthly_payment_total` 表示月度固定支出，包括债务月供和持续订阅费用。
- `debt_to_income_ratio = monthly_payment_total / income_total`。
- `monthly_surplus = income_total - monthly_payment_total`。
- `cashflow_series[].debt_payment` 与 `monthly_payment_total` 口径一致，包括当月仍然有效的债务月供和订阅费用。
- `risk.score` 为 0-100 整数。
- `risk.level` 只能为：`低风险`、`关注`、`中风险`、`高风险`。
- `cashflow_series` 长度等于 `forecast_months`。
- IRR 无法求解时 `status` 为 `unavailable`，不得编造数值。
- 所有结果包含参数版本和计算版本。

```json
{
  "request_id": "req_7f2c",
  "status": "completed",
  "degraded": false,
  "tool_activity": [
    {
      "tool": "run_risk_assessment",
      "status": "succeeded",
      "latency_ms": 18
    }
  ],
  "assessment": {},
  "explanation": {
    "summary": "当前负债叠加已经对月度现金流形成明显压力。",
    "risk_sources": [
      {
        "dimension_id": "debt_to_income",
        "title": "月供占用较高",
        "detail": "固定月供占可支配收入的比重偏高，应优先核对负债结构。"
      }
    ],
    "actions": [
      "核对每笔分期的真实年化和剩余期数。",
      "先处理成本最高或最挤压现金流的负债。"
    ],
    "education": [
      "低月供不等于低总成本，期限和费用会改变真实资金成本。"
    ],
    "questions_to_consider": [
      "这笔新增月供是否会挤压未来三个月的基本生活支出？"
    ],
    "boundary_notice": "本结果仅供金融教育与个人负债压力自查参考，不构成信贷审批、授信、放款或投资建议。"
  },
  "error": null
}
```

### 5.1 explanation 字段约束

- `summary`：只表达定性结论，不新增金额和利率。
- `risk_sources`：必须关联 `dimension_id` 或 `debt_id`。
- `actions`：不得推荐借贷产品、平台、额度或“以贷养贷”。
- `education`：解释真实成本、现金流和理性消费，不承诺收益。
- `questions_to_consider`：帮助用户自查，不替用户做决定。
- `boundary_notice`：固定边界声明。

## 7. 核心接口

### 7.1 创建会话

```http
POST /api/v1/sessions
Content-Type: application/json
```

请求体：`AssessmentRequest`。

响应：

```json
{
  "session_id": "anon_20261101_a1b2c3",
  "expires_in_seconds": 1800
}
```

### 7.2 运行 Agent

```http
POST /api/v1/agent/assess
Content-Type: application/json
```

请求：

```json
{
  "session_id": "anon_20261101_a1b2c3"
}
```

响应：`AgentResponse`。

验收要求：

- 响应中的 `tool_activity` 至少包含 `run_risk_assessment`。
- `assessment` 存在。
- `explanation` 通过 Schema 校验。
- `degraded=false` 表示模型和工具链路正常。

### 7.3 情景模拟

情景模拟不暴露单独的 HTTP 保存接口。用户通过 `/api/v1/agent/chat`
描述假设分期，编排器把部分 `ScenarioDraft` 保存在进程内，并在信息完整后调用
`simulate_new_installment(session_id, scenario_id)`。

响应中的 `scenario` 包含 `base_assessment`、`scenario_assessment`、
月供/结余/风险分变化及前后风险等级。`nominal_apr` 可为 `null`，此时结果包含
“名义利率未知、真实成本解释受限”的确定性警告。

## 8. 错误码

| 错误码 | 含义 | HTTP |
|---|---|---:|
| `VALIDATION_ERROR` | 字段非法 | 422 |
| `INCOME_REQUIRED` | 收入合计为 0 | 422 |
| `SESSION_NOT_FOUND` | 会话不存在或过期 | 404 |
| `SESSION_EXPIRED` | 会话超过 TTL | 410 |
| `TOOL_NOT_FOUND` | 工具不存在 | 500 |
| `TOOL_ARGUMENT_ERROR` | 工具参数不合法 | 422 |
| `ASSESSMENT_UNAVAILABLE` | 计算或 IRR 不可用 | 503 |
| `LLM_TIMEOUT` | 模型超时 | 200 或 503，允许降级响应 |
| `LLM_OUTPUT_INVALID` | 模型输出不符合 Schema | 200，标记降级 |
| `SAFETY_BLOCKED` | 输出触发安全规则 | 200，返回模板 |
| `RATE_LIMITED` | 请求频率受限 | 429 |
| `INTERNAL_ERROR` | 未预期错误 | 500 |

统一错误体：

```json
{
  "request_id": "req_7f2c",
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请检查收入字段",
    "fields": {
      "monthly_disposable_allowance": "不能为负数"
    }
  }
}
```

## 9. 会话与隐私

- `SessionStore` 只存在进程内存。
- TTL 默认 30 分钟。
- API 不返回完整原始输入。
- 日志只记录 `request_id`、`session_id` 哈希、工具名、耗时和状态。
- 删除会话后不可恢复。
- MVP 不使用数据库、文件、CSV 或 localStorage。

## 10. 契约测试要求

- 每一个接口至少有一个成功测试和一个失败测试。
- 请求和响应必须经过 Pydantic 校验。
- `assessment_result` 字段不得缺失。
- `explanation` 必须包含固定边界声明。
- AgentResponse 不得包含原始财务明细。
- 工具调用轨迹不得包含模型思维链。

## M4-B 统一对话补充契约

2026-11-06 增加 `POST /api/v1/agent/chat`。请求为：

```json
{
  "conversation_id": "conv_001",
  "message": "什么是IRR？"
}
```

响应状态包括：

- `needs_more_info`：需要补充信息；
- `ready_for_confirmation`：自然语言草稿已完整，等待用户确认；
- `education_answer`：基于审核中教育卡片的科普回答；
- `completed`：风险评估解释或情景模拟完成；
- `out_of_scope`：拒绝借贷平台、审批、额度等越界请求；
- `error`：可恢复错误。

新增工具：

- `retrieve_education_topic(topic_id)`
- `simulate_new_installment(session_id, scenario_id)`

M4-B 上下文只保存在进程内存，TTL 30 分钟；不保存完整聊天原文。

## M4-A/M4-B LLM 数据流补充

自然语言链路为：

用户当前轮文本
-> 专用抽取/科普/情景模型
-> 结构化草稿或结构化回答
-> Pydantic 校验
-> 创建匿名会话
-> M2 确定性计算
-> AssessmentResult
-> 报告解释模型

边界：

- 报告解释模型只接收 AssessmentResult；
- 自然语言抽取、科普和情景模型只接收当前轮必要文本；
- 不发送完整聊天历史或完整财务明细；
- 原始文本不写入 DraftStore、ConversationStore、日志、数据库或 localStorage。

## M5.6 有界追问与上下文记忆契约

### 1. `/api/v1/agent/chat` 轮数字段

`AgentChatResponse` 和 `/api/v1/agent/intake` 的 `IntakeResponse` 增加：

```json
{
  "clarification_turns": 0,
  "max_clarification_turns": 8,
  "remaining_clarification_turns": 8
}
```

计数规则：

- 首次用户输入始终不占追问轮次；
- 首次输入后，用户每次补充若仍返回 `needs_more_info`，才消耗一轮；
- 默认 `MAX_CLARIFICATION_TURNS=8`，允许配置范围 `1-50`；
- 已使用轮数达到上限后，下一次输入返回 `clarification_limit`，不调用 LLM、不创建正式评估会话、不覆盖已有草稿；
- 上限响应保留结构化草稿和预览，提示改用结构化表单或重新开始。

### 2. 新增会话清理接口

```http
DELETE /api/v1/agent/conversations/{conversation_id}
```

删除时同时清理：

- `ChatMemoryStore` 中的短期消息；
- `DraftStore` 中的结构化草稿；
- `ConversationStore` 中的结构化上下文。
- `ScenarioStore` 中绑定该 conversation 的情景草稿；
- Conversation 绑定的匿名 `SessionStore` 财务会话。

该接口不删除认证账号或认证会话；认证数据库与聊天记忆完全分离。

### 3. ChatMemoryStore

只存在进程内存：

- `messages` 默认最多 8 条，可配置 `CHAT_MEMORY_MAX_MESSAGES=8`，范围 1-10；
- TTL 默认 1800 秒，可配置 `CHAT_MEMORY_TTL_SECONDS=1800`，范围 1-86400；
- 后台清理默认每 60 秒运行一次，可通过 `RETENTION_SWEEP_SECONDS=60` 配置；
- 结构化上下文包括 `last_intent`、`last_topic`、`last_assessment_id`、`last_answer_type`、`last_tool`；
- 不写 SQLite、CSV、日志、数据库或 localStorage；
- 原始聊天只在内存中短期保存，完整历史不发送给任何 LLM。

### 4. 发送范围

| 任务 | 允许发送 | 禁止发送 |
|---|---|---|
| 信息抽取 | 当前用户消息、当前结构化草稿、上一轮未回答的问题、必要 Schema | 完整聊天历史、完整财务档案 |
| 科普回答 | 当前问题、当前科普卡片、主题、必要 Schema | 完整聊天历史、个人财务明细 |
| 风险解释 | `AssessmentResult`、Explanation Schema | 原始聊天、草稿、完整财务档案 |
| 情景模拟 | 当前情景描述、当前结构化会话状态、必要 Schema | 完整聊天历史、报告模型上下文 |

`clarification_limit` 是 M5.6 新增的稳定响应状态，页面不得把它当作普通错误，而应显示重新开始或结构化表单入口。

`ConversationState.active_task` 取值为 `intake`、`scenario` 或 `null`，并通过
`active_scenario_id` 恢复情景部分草稿。用户在当前活动中发送明确越界请求时仍优先返回
`out_of_scope`。
## M5.6 审查修复补充

### 未知利率

草稿层增加：

```text
nominal_apr_status = not_mentioned | unknown | provided
```

- `not_mentioned`：尚未提到利率，可以追问一次；
- `unknown`：用户明确不知道，不可继续重复追问；
- `provided`：已经提供具体利率；
- 正式 `AssessmentRequest.debts[].nominal_apr` 允许 `null`；
- `null` 绝不转换为 0；
- 评估结果包含“名义利率未知，真实成本解释受限”的 warning。

### 对话错误状态

`POST /api/v1/agent/chat` 对可恢复错误使用真实 HTTP 状态：

| 状态 | 场景 |
|---|---|
| 404 | conversation、session 或 scenario 不存在 |
| 410 | conversation、session 或 scenario 过期 |
| 409 | 草稿/情景未完成，或已有 20 笔债务 |
| 422 | 抽取失败、工具参数非法或结果结构非法 |

聊天错误返回现有统一错误体：

```json
{
  "request_id": "req_...",
  "error": {
    "code": "SCENARIO_NOT_FOUND",
    "message": "情景数据不存在或已经清理，请重新描述这笔新增分期。"
  }
}
```

### 风险解释 grounding

风险解释模型只能选择 AssessmentResult 中存在的 risk dimension。后端不直接采用模型生成的 summary、risk source 文案、actions 或 education 文本，而是根据合法 dimension_id 从固定模板重新组装 Explanation。任一维度不合法、包含未授权数字或触发安全词时，直接降级为模板解释。

### 确认后 session

草稿确认成功后，`AgentResponse` 增加可选 `session_id`。Streamlit 将其写入页面状态；删除 conversation 时后端还会按 ConversationState 中的 session_id 级联删除 SessionStore。
### M5.7.1 多笔债务与还款额字段

草稿层新增以下内部字段：

- `total_remaining_repayment`：用户明确描述的总剩余还款额；
- `final_payment`：总还款额不能整除月供时的最后一期金额；
- `derived_fields`：记录由系统根据输入推导出的字段；
- `kind`：区分 installment、subscription 和待确认状态。

这些字段只属于草稿契约，不直接进入 M2。正式 `AssessmentRequest` 仍使用：

```text
remaining_principal
monthly_payment
remaining_periods
nominal_apr
```

`total_remaining_repayment` 不得被静默当作 `remaining_principal`。剩余期数只允许由确定性归一化函数推导。
## M5.7.2 草稿与意图契约补充

- `DebtDraft` 新增 `original_amount` 和 `remaining_ratio`，仅用于进程内草稿推导；
- `DraftState` 新增 `pending_field` 和 `no_progress_turns`；
- `remaining_principal` 仍表示当前剩余欠款本金；
- `total_remaining_repayment` 仍表示总共还要还的钱；
- 原价和剩余比例不能替代用户明确的剩余本金；
- `current_debt_index` 对原始 `draft.debts` 索引稳定，不因已结清债务被过滤而错位；
- 内部意图新增 `general_help`，公开响应继续使用现有合法 ChatStatus；
- 新增字段继续只存在进程内存，不进入 AssessmentRequest。
