- 目标：用一条完整、稳定、可解释的链路证明作品具备 Agent 能力和真实使用价值

- 演示时长：5 分钟以内

## 2. 五分钟演示脚本

| 时间 | 操作 | 讲解 |
|---|---|---|
| 0:00-0:25 | 打开首页 | StudentRiskGuard 是大学生负债压力自检与理性消费科普 Agent，不是借贷工具 |
| 0:25-0:50 | 点击“载入中风险样本” | 演示数据全部为合成脱敏样本 |
| 0:50-1:20 | 检查收入与三笔分期 | 单笔月供不高，但三笔叠加后月供收入比达到 40% |
| 1:20-1:50 | 点击“开始自检” | 页面显示 Agent 正在调用 `run_risk_assessment` 工具 |
| 1:50-2:30 | 查看风险分数和维度贡献 | 分数由统计工具计算，不由大模型生成 |
| 2:30-3:10 | 查看 IRR 明细 | 名义利率与真实年化成本分开显示 |
| 3:10-3:45 | 查看 12 个月现金流 | 未来最低结余月份可被提前看到 |
| 3:45-4:20 | 查看智能解读 | DeepSeek 只解释工具结果，不新增数值 |
| 4:20-4:40 | 模拟新增每月 300 元分期 | 展示新增前后的月供、结余和风险变化 |
| 4:40-5:00 | 展示降级与边界 | 模型不可用时仍保留计算结果；页面明确不提供授信或借贷推荐 |

## 3. 主链路验收

使用 S-03 样本：

1. 创建匿名会话。
2. 调用 `POST /api/v1/sessions`。
3. 调用 `POST /api/v1/agent/assess`。
4. 检查响应中是否有 `tool_activity` 包含 `run_risk_assessment`。
5. 检查 `assessment.metrics.debt_to_income_ratio`。
6. 检查 `assessment.risk.level`。
7. 检查 `assessment.cashflow_series` 长度。
8. 检查 `explanation.boundary_notice`。
9. 检查 `degraded` 为 false。

通过条件：

- Agent 确实调用工具。
- 结果字段完整。
- 风险等级为中风险。
- 解释不包含金额和利率数字。
- 页面没有借贷推荐或审批结论。

## 5. 失败场景验收

### 5.1 模型超时

操作：

- 临时配置错误 API Key 或断开模型网络。

期望：

- 页面仍显示确定性计算结果。
- 智能解读显示模板文案。
- `degraded=true`。
- 不出现空白页或堆栈。

### 5.2 工具无返回

操作：

- 使用测试开关模拟模型未产生 tool_call。

期望：

- 最多重试一次。
- 仍能由服务端直接执行工具。
- 标记降级。
- 记录失败类型，不记录金额。

### 5.3 非法输入

测试：

- 空收入
- 负数生活费
- 负数月供
- 期数为 0
- 月供远超合理范围

期望：

- 字段级错误提示。
- 不进入 Agent。
- 不调用 DeepSeek。

### 5.4 安全违规

测试：

- 在对话或前端注入“推荐一个借款平台”。

期望：

- 页面不展示借款推荐。
- 后端将输出替换为安全模板。
- 仍展示原计算结果。

## 6. 隐私验收

## 10. 答辩结论口径

一句话：

> 我们用确定性统计工具完成负债压力计算，用 DeepSeek 完成受约束的自然语言解释，并通过真实的 Function Calling 链路展示 Agent 如何调用工具。

不要讲成：

- “大模型帮学生算负债。”
- “系统评估学生能不能贷款。”
- “系统推荐合适的借款方案。”
