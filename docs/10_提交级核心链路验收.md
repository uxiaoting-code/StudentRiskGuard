# StudentRiskGuard 提交级 Agent 核心链路验收基线

- 文档版本：SUBMISSION-GATE-1.0
- 目的：确认按 M0-M9 完成后，项目能够形成一个可提交、可公网访问、可真实调用工具的 Agent
- 结论：只要 M0-M7 全部通过，项目即达到初赛“可提交 Agent”标准；M8 只负责打包和冻结

## 1. 什么叫“可提交 Agent”

本项目不把以下情况视为完成：

- 只有静态页面，没有真实计算。
- 页面直接调用 Python 计算结果，没有 Agent 工具调用。
- 把原始财务数据交给大模型，让模型算分。
- 只有模板解释，没有真实 DeepSeek 解释链路。
- 模型失败就白屏，没有降级。
- 只在本地能运行，没有公开链接。
- 只有低风险样本能跑通。

本项目把以下链路视为初赛提交最低标准：

```text
用户输入
-> 匿名内存会话
-> Agent 调用 run_risk_assessment(session_id)
-> 确定性计算工具执行
-> 返回 AssessmentResult
-> DeepSeek 生成受约束解释
-> 安全检查
-> 网页展示风险报告
```

其中必须存在一条可验证的 Agent 工具调用轨迹。

## 2. 里程碑与提交门槛

| 门槛 | 模块 | 必须证明什么 | 不通过后果 |
|---|---|---|---|
| G1 计算门 | M2 | 四类样本可算出指标、IRR、分数和现金流 | 无法证明结果可信 |
| G2 工具门 | M3 | 输入经 ToolExecutor 得到 AssessmentResult | 只有普通后端，不是 Agent |
| G3 Agent 门 | M4 | DeepSeek 真实返回 `run_risk_assessment` tool_call | 无法证明“Agent 调用工具” |
| G4 页面门 | M5 | 用户能从网页完成输入到报告 | 作品不可试用 |
| G5 安全门 | M6 | 违规输出被拦截，模型断开可降级 | 不具备提交可靠性 |
| G6 公网门 | M7 | 公网链接完成四类样本闭环；S4/S5 参数已校准或明确保留初版参数 | 初赛无法验收或参数口径不清 |
| G7 提交门 | M8 | Demo、截图、README、版本冻结 | 材料不完整 |

提交结论：

- **M0-M7 全部通过：具备可提交的 Agent 作品。**
- **M8 完成：具备完整初赛提交包。**
- **M9 可选：自然语言录入不影响核心提交资格。**

## 2.2 问卷专项与开发顺序

问卷不是 M1-M6 的全局前置条件：

- M0 可立即开始；只需在 M0 验收前完成字段映射核对。问卷文字和选项可继续迭代，新增模型字段才触发契约变更。
- S1-S5 与 M1-M6 并行。
- M2/M5 先用初版评分卡开发。
- M7 前必须完成 S4/S5，或保留初版参数并写明样本限制。
- 不能以“问卷还在收”为理由不开始工程开发，也不能在没有校准结果时声称参数已经由问卷校准。

## 3. 一条主链路的具体验收

主样本：S-03 中风险样本。

### 步骤 1：打开公开页面

操作：

- 通过 HuggingFace Spaces 链接打开页面。

必须看到：

- 产品名称和一句话定位。
- “无需注册，打开即可试用”说明。
- 金融教育与自查边界声明。
- “开始自检”和四类样本入口。

证据：

- 公开 URL。
- 首页截图。

### 步骤 2：载入合成样本

操作：

- 点击“中风险样本”。

必须看到：

- 稳定可支配生活费 2200。
- 兼职收入 800。
- 三笔分期：月供 520、380、300。
- 页面标记“合成演示数据”。

证据：

- 输入页截图。
- 网络请求中无身份字段。

### 步骤 3：提交输入并创建匿名会话

操作：

- 点击“开始风险自检”。

后端必须：

1. 校验输入。
2. 在内存创建 `session_id`。
3. 保存 `AssessmentRequest`。
4. 不写数据库、不写文件。
5. 不把原始明细发送给 DeepSeek。

证据：

- `POST /api/v1/sessions` 响应。
- 会话对象仅存在于内存。
- `session_id` 为匿名随机串。

### 步骤 4：Agent 调用工具

必须发生：

```text
DeepSeek tool_call:
run_risk_assessment({"session_id": "..."})
```

必须满足：

- 模型输入只有 session_id 和任务指令。
- 模型输入不包含原始生活费、月供和分期明细。
- 工具名必须为 `run_risk_assessment`。
- 工具调用必须有 request_id 和耗时记录。

证据：

- `tool_activity` 包含 `run_risk_assessment`。
- 后端日志只记录工具名和状态，不记录金额。
- 失败场景能显示“未调用工具”并降级。

如果模型没有真实调用工具，G3 不通过，不能把项目描述为“Agent 已跑通”。

### 步骤 5：确定性工具执行

工具必须：

1. 读取匿名会话。
2. 计算月收入、月供合计、月供收入比和月结余。
3. 计算逐笔 IRR。
4. 计算 0-100 分和四级风险。
5. 生成 12 个月结余序列。
6. 返回 AssessmentResult。

S-03 期望：

- 月收入 3000。
- 月供合计 1200。
- 月供收入比 0.40。
- 债务笔数 3。
- 风险等级为中风险。
- 现金流序列长度为 12。

证据：

- AssessmentResult JSON。
- pytest 固定样本断言。
- 手工复算记录。

### 步骤 6：DeepSeek 生成解释

模型必须只读取 AssessmentResult，并输出：

```json
{
  "summary": "...",
  "risk_sources": [],
  "actions": [],
  "education": [],
  "questions_to_consider": [],
  "boundary_notice": "本结果仅供金融教育与个人负债压力自查参考，不构成信贷审批、授信、放款或投资建议。"
}
```

必须满足：

- 不新增金额、利率、分数和期数。
- 不推荐借贷产品和平台。
- 不输出审批或额度结论。
- 风险来源关联 `dimension_id` 或 `debt_id`。

证据：

- 模型输出 JSON。
- Schema 校验结果。
- 数值一致性检查结果。

### 步骤 7：安全检查

必须检查：

- 固定边界声明存在。
- 解释 JSON 合法。
- 无未授权数值。
- 无借贷推荐、审批结论、收益承诺和以贷养贷。

失败处理：

- 原解释丢弃。
- 返回模板解释。
- `degraded=true`。
- 页面仍展示确定性计算结果。

### 步骤 8：网页展示

页面必须展示：

- 中风险等级。
- 0-100 压力分。
- 月供收入比。
- 三笔 IRR。
- 四维贡献。
- 12 个月现金流。
- 智能解读。
- 固定边界声明。

证据：

- 结果页截图。
- 数值与 AssessmentResult 一一对应。

### 步骤 9：新增分期模拟

操作：

- 模拟新增每月 300 元的分期。

必须展示：

- 新增前后月供。
- 新增前后月供收入比。
- 新增前后风险分和等级。
- 新增前后最低结余月份。
- 原始结果不被覆盖。

证据：

- 模拟前后对比截图。
- `simulate_new_installment` 工具轨迹。
- 前后差值计算结果。

## 5. 部署方式确认

初赛主入口必须采用 Streamlit 单进程部署，避免 FastAPI 和 Streamlit 两个独立进程导致内存会话不共享。

- Streamlit 页面直接调用同进程的 `AgentRunner` 和 `SessionStore`。
- FastAPI 作为同仓库接口适配层，用于本地测试和接口证明。
- 如果部署两个独立进程，必须先实现共享会话或签名会话 token；否则 `run_risk_assessment(session_id)` 可能找不到会话。
- MVP 不引入 Redis 或数据库来解决该问题。
