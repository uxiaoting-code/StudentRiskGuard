# StudentRiskGuard 匿名问卷设计与数据收集计划

- 文档版本：SURVEY-PLAN-1.1
- 修订说明：根据搭档阅读反馈，简化金额区间、调整题序、增加名词说明、减少模糊选项并降低隐私防备。
- 负责人：经济统计同学
- 系统使用方：计算机同学只读取冻结后的评分参数，不直接使用个人答卷
- 用途：校准指标分布、权重和阈值，验证用户痛点与功能优先级，支撑商业计划书中的数据和模型口径

## 1. 问卷的重要性

问卷不是形式材料，它直接影响项目可信度：

1. 为月供收入比、分期笔数、兼职收入占比等指标提供校园样本分布。
2. 为打分卡权重、分档和风险阈值提供初版校准依据。
3. 为四类合成演示样本提供合理范围，避免样本完全凭感觉设置。
4. 为商业计划书中的痛点、用户需求和功能优先级提供可解释证据。
5. 让统计同学的计算口径与计算机同学的产品字段保持一致。

问卷不用于授信、征信、借贷审批，也不作为系统明细输入。原始答卷不进入产品数据库，只用于匿名汇总分析。

## 2. 什么时候做

问卷工作与开发并行，不阻塞 M1-M3 的代码实现。

| 时间 | 问卷任务 | 与开发模块的关系 |
|---|---|---|
| D0-D1 | 设计问卷、3-5 人预测试、修订题目 | 早于或同步 M0，完成字段对齐 |
| D1 | 正式发放，使用匿名问卷平台 | 与 M0/M1/M2 并行 |
| D1-D4 | 收集答卷，目标至少 80 份有效样本，力争 100-150 份 | 与 M1、M2、M3 并行 |
| D4-D5 | 数据清洗、描述统计、EDA | 与 M3/M4 并行 |
| D5-D6 | 校准权重和阈值，生成新的参数版本 | 在 M5/M6 验收前完成 |
| D7 | 冻结参数版本，写入报告和答辩材料 | 在 M7 公网部署前完成 |
| D8-D10 | 只做解释与展示，不再修改核心参数 | M7/M8 |

### 2.1 关键原则

- 先用初版 `scorecard.example.json` 让开发继续，不等问卷完成才写代码。
- 问卷完成后只更新配置文件和参数版本，不重写计算函数。
- 如果有效样本不足，保留初版参数，并在报告中说明样本限制，不宣称已完成全国性校准。
- D7 后冻结参数，不在答辩前临时调权重。

## 2.2 是否必须完成全部问卷任务才能开始开发

不是。

- M0 可以立即开始；只需在 M0 验收前核对问卷题目与模型字段的覆盖关系，不需要等问卷最终定稿。
- S1-S5 问卷发放、回收、清洗和校准与 M1-M6 并行。
- M2 的计算函数使用初版 `scorecard.example.json` 开发，不等待真实问卷。
- M5/M6 可先用初版参数做页面和安全逻辑。
- M7 公网部署前必须完成 S4/S5，或者保留初版参数并明确样本限制。
- 问卷不阻塞 M1-M6，但阻塞最终参数冻结和提交口径。

## 2.3 问卷回收期间经济统计同学可以做什么

问卷回收不影响统计同学继续开发。不要等全部答卷收齐再开始 M2。

| 阶段 | 可以完成的工作 | 不要提前做什么 |
|---|---|---|
| 发放前 | 定稿问卷、预测试、字段对齐、写数据字典、确认题目编码 | 不要提前用少量答卷宣布校准完成 |
| D1-D4 回收期间 | 实现 M2 指标、IRR、打分卡、现金流；生成合成数据；写单元测试；准备四类演示样本 | 不要用尚未清洗的数据直接改参数 |
| D4-D5 清洗期间 | 编写清洗脚本、区间中位数规则、描述统计、EDA、样本质量控制 | 不要把原始答卷放进应用仓库 |
| D5-D6 校准期间 | 根据汇总分布更新权重和阈值，形成参数版本和校准说明 | 不要重写计算公式或页面逻辑 |
| D6-D7 冻结前 | 复核样本量、代表性限制、答辩口径和最终参数 | 不要在 D7 后临时改权重 |
| 全程 | 审核 Prompt 边界、金融科普内容、安全测试用例和页面指标名称 | 不要让 LLM 参与数值计算 |

### 2.3.1 需要等问卷数据才能做的部分

- 最终权重和阈值的校准。
- 样本分布和代表性说明。
- 校准版评分卡参数。
- 基于问卷的描述统计和 EDA。
- 最终商业计划书中的数据证据。

### 2.3.2 不需要等问卷数据就能做的部分

- `metrics.py`、`irr.py`、`scorecard.py`、`cashflow.py`。
- 合成数据生成脚本。
- 四类演示样本。
- 单元测试和边界测试。
- 问卷数据清洗脚本和分析模板。
- 参数版本结构和参数加载逻辑。
- Prompt 边界、科普文案和安全测试用例。

## 3. 调查对象与抽样

- 对象：国内全日制在校本科生、研究生。
- 方式：匿名、自愿、在线问卷，建议使用问卷星。
- 渠道：班级群、学生组织、校园社团、课程群；不得强迫或诱导填写。
- 目标：至少 80 份有效答卷；100-150 份更利于分组观察。
- 说明：这是黑客松项目的探索性样本，不代表全国大学生总体。
- 不收集：姓名、学号、手机号、身份证、银行卡、学校名称、平台账号、真实账单、征信信息。

## 4. 知情说明

问卷开头必须展示：

> 本问卷用于大学生负债压力自检工具的研究与模型校准。问卷匿名、自愿，不收集姓名、学号、手机号、身份证、银行卡、学校名称、平台账号和真实账单。数据仅以汇总统计形式用于项目分析和演示，不用于授信、贷款审批、征信或任何借贷推荐。您可随时退出，不会产生任何影响。

| 剩余期限 | Q6 | 校准期限和月供压力 |

| 真实成本认知 | Q15、Q17-Q21 | 验证名词说明前后理解变化，不直接用自报利率算 IRR |
| 现金流压力 | Q11-Q14 | 校准风险等级和压力解释 |
| 功能优先级 | Q22-Q25 | 指导 MVP 页面和科普内容 |
| 注意力检查 | Q10 | 剔除未通过答卷 |

## 9. 参数校准方法

1. 用 Q4、Q7、Q27、Q28 的区间中位数估算月供收入比，并计算分位数。
2. 用 Q2 的分布调整负债叠加维度的分档点；Q2 使用 1-2 笔、3-4 笔、5 笔及以上宽区间。
3. 用 Q29 和 Q28/Q27 的收入占比调整收入稳定性维度。
4. Q7 选择“无法估计”时，不把它当缺失，优先用 Q4、Q27、Q28 估算。
5. IRR 阈值不能仅靠学生自报数字校准；使用合成分期场景、费用案例和消费者成本常识进行校准，用 Q18-Q21 验证理解水平。
6. 风险等级阈值结合 DTI 分布、Q11-Q14 的现金流压力题和专家复核确定。
7. 任何参数变更都要更新 `scorecard` 版本和变更记录。
8. 问卷只提供汇总依据，不把个体答卷直接作为用户输入。
