# M2 输入输出与契约说明

- 契约版本：`M2-CONTRACT-2026.11.04`
- 模型版本：`calc-2026.11-m2-final`
- 参数版本：`scorecard-2026.11-m2-final`
- 状态：最终版
- 原则：所有指标由后端计算，DeepSeek 只解释已经计算完成的 `AssessmentResult`

## 1. 唯一事实源

| 内容 | 文件 |
|---|---|
| 最终契约清单 | `contracts/m2_final_contract.json` |
| 输入端口 | `contracts/assessment_request.schema.json` |
| 输出端口 | `contracts/assessment_result.schema.json` |
| 运行时评分卡 | `src/riskguard/core/scorecard.json` |
| 契约评分卡副本 | `contracts/scorecard.example.json` |
| 五套回归样本 | `contracts/demo_cases.json` |
| Pydantic 输入输出模型 | `src/riskguard/models/assessment.py` |
| 总计算入口 | `src/riskguard/core/engine.py` |

## 2. 系统参与者

| 参与者 | 负责内容 | 不负责内容 |
|---|---|---|
| Streamlit/Web 表单 | 收集用户输入并构造 `AssessmentRequest` | 不计算 DTI、IRR、分数 |
| 自然语言解析器 | 把非结构化文本转成 `AssessmentRequest` 草稿 | 不直接调用评分卡，不生成最终结论 |
| 会话存储 | 按 `session_id` 保存匿名输入 | 不持久化真实身份信息 |
| M2 计算内核 | 计算指标、IRR、评分和现金流 | 不调用任何大模型 |
| 风险评分卡 | 提供冻结阈值和分值 | 不读取用户身份数据 |
| DeepSeek Agent | 把 `AssessmentResult` 解释成通俗文字 | 不重算或修改任何数值、分数和等级 |
| 结果页面 | 展示分数、等级、维度贡献、IRR、现金流和建议 | 不自行制造计算结果 |

## 3. 总流程

```text
用户表单或自然语言
  -> AssessmentRequest
  -> 后端 compute_metrics
  -> 后端 compute_irr_results
  -> 后端 compute_risk
  -> 后端 compute_cashflow
  -> AssessmentResult
  -> DeepSeek 解释
  -> 页面展示
```

Agent 工具只接收 `session_id`。后端根据 `session_id` 读取会话并执行 `run_assessment`，再把 `AssessmentResult` 交给解释模型。

## 4. 输入端口：AssessmentRequest

### 4.1 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `session_id` | string | 是 | 匿名会话ID，只允许字母、数字、下划线、短横线 |
| `income` | object | 是 | 收入对象 |
| `debts` | array | 是 | 债务数组，可以为空数组 |
| `savings_balance` | number | 否 | 当前存款，默认0，只用于现金流缓冲 |
| `recurring_subscriptions` | array | 否 | 持续订阅，默认空数组 |
| `behavior` | object | 否 | 自报行为与韧性信息，默认中性值 |
| `forecast_months` | integer | 否 | 预测月数，1-36，默认12 |

### 4.2 income

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `monthly_disposable_allowance` | number | 是 | 每月可支配生活费，0-1,000,000 |
| `monthly_part_time_income` | number | 是 | 每月兼职收入，0-1,000,000 |

两项合计必须大于0。

### 4.3 debts[]

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | string | 是 | 会话内唯一债务ID |
| `label` | string | 是 | 仅用于展示的债务类型 |
| `remaining_principal` | number | 是 | 剩余本金，大于0 |
| `monthly_payment` | number | 是 | 每月合同还款额，大于0 |
| `remaining_periods` | integer | 是 | 剩余期数，1-120 |
| `nominal_apr` | number/null | 否 | 名义年利率，0-1；未知时为 `null`，只作参考，不参与 IRR 计算 |

债务数量最多20笔，`id`不可重复。

### 4.4 recurring_subscriptions[]

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `label` | string | 是 | 订阅名称 |
| `monthly_cost` | number | 是 | 每月订阅费用，大于0 |

订阅不是负债，不计算本金、期数和IRR，但进入月度固定支出和现金流。

### 4.5 behavior

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---:|---|
| `borrow_to_repay` | boolean | false | 是否曾以贷养贷 |
| `strict_overdue_count` | integer | 0 | 过去12个月逾期次数，0-100 |
| `insufficient_months_last_3` | integer | 0 | 过去3个月资金不足月份数，0-3 |
| `income_drop_30_cannot_cover` | boolean | false | 收入下降30%时是否无法覆盖 |
| `financial_cognition_score` | number/null | null | 金融认知得分，1-5 |

这些字段只进入“行为与韧性”评分，不进入DTI或IRR。

## 5. 后端计算指标

| 指标 | 公式或定义 |
|---|---|
| `income_total` | 可支配生活费 + 兼职收入 |
| `monthly_payment_total` | 所有债务月供 + 所有订阅月费 |
| `debt_to_income_ratio` | `monthly_payment_total / income_total` |
| `remaining_debt_total` | 所有债务剩余本金之和 |
| `debt_count` | 债务数组长度 |
| `monthly_surplus` | `income_total - monthly_payment_total` |
| `surplus_ratio` | `monthly_surplus / income_total` |
| `monthly_irr` | 使剩余本金和未来固定月供净现值为0的月利率 |
| `annualized_irr` | `(1 + monthly_irr)^12 - 1` |
| `cumulative_surplus` | 从第1个月开始的累计月度结余 |

`monthly_payment_total` 和输出现金流中的 `debt_payment` 都表示“债务月供 + 当期订阅费用”。这是正式字段语义。

## 6. 冻结评分卡

| 维度ID | 分值 | 规则 |
|---|---:|---|
| `debt_to_income` | 35 | <30%得0；30%-39%得12；40%-49%得24；≥50%得35 |
| `debt_stack` | 15 | ≤2笔得0；3笔得6；4笔得10；≥5笔得15 |
| `real_cost` | 20 | <10%得0；10%-23.9%得6；24%-35.9%得12；≥36%得20 |
| `behavior_resilience` | 30 | 以贷养贷11；严格逾期6；资金不足2/4/6；收入下降无法覆盖4；认知薄弱3 |

行为维度逐项累加并封顶30分，全部子项触发时正好30分。

风险等级：

| 总分 | 等级 |
|---|---|
| 0-24 | 低风险 |
| 25-49 | 关注 |
| 50-74 | 中风险 |
| 75-100 | 高风险 |

## 7. 输出端口：AssessmentResult

### 7.1 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `assessment_id` | string | 确定性评估ID |
| `request_id` | string | 确定性请求ID |
| `model_version` | string | `calc-2026.11-m2-final` |
| `parameter_version` | string | `scorecard-2026.11-m2-final` |
| `metrics` | object | 核心指标 |
| `irr_results` | array | 每笔债务IRR |
| `risk` | object | 总分、等级、维度和主要贡献项 |
| `cashflow_series` | array | 逐月现金流 |
| `warnings` | string[] | 可展示警告 |
| `assumptions` | object | 币种、固定收入和预测期 |

### 7.2 metrics

| 字段 | 类型 |
|---|---|
| `income_total` | number |
| `monthly_payment_total` | number |
| `debt_to_income_ratio` | number |
| `remaining_debt_total` | number |
| `debt_count` | integer |
| `monthly_surplus` | number |
| `surplus_ratio` | number |

### 7.3 irr_results[]

| 字段 | 类型 | 说明 |
|---|---|---|
| `debt_id` | string | 对应债务ID |
| `monthly_irr` | number/null | 月IRR |
| `annualized_irr` | number/null | 有效年化 |
| `status` | enum | `ok`或`unavailable` |
| `assumption` | string | 现金流假设 |

状态为`ok`时两个IRR字段必须有数值；状态为`unavailable`时不得填入猜测值。

### 7.4 risk

| 字段 | 类型 | 说明 |
|---|---|---|
| `score` | integer | 0-100总分 |
| `level` | enum | 四级风险等级 |
| `dimensions` | array | 固定四个维度及其贡献 |
| `top_contributors` | string[] | 贡献最高的1-3个维度ID |

### 7.5 cashflow_series[]

| 字段 | 类型 |
|---|---|
| `month_index` | integer |
| `income` | number |
| `debt_payment` | number |
| `surplus` | number |
| `cumulative_surplus` | number |

数组长度必须等于`assumptions.forecast_months`。

## 8. Agent边界

- Agent工具名固定为`run_risk_assessment`。
- 工具参数只有`session_id`。
- 原始财务明细不能作为工具参数发送给大模型。
- 大模型只接收并解释`AssessmentResult`。
- 大模型不得重算DTI、IRR、分数或风险等级。
- DeepSeek超时、格式错误或无工具调用时，后端结果仍必须返回。
- 解释失败时使用固定模板，不得生成猜测数值。

## 9. 契约不变量

- `debts`必须存在，无负债时传空数组。
- 所有金额单位为人民币元。
- 所有利率使用小数，12%写作`0.12`。
- 风险维度ID必须与评分卡维度ID完全一致。
- 风险分数等于四个维度贡献之和并按half-up取整。
- 风险等级只能从评分卡风险区间产生。
- 输入和输出均禁止额外字段。
- 原始问卷、XLSX和BNPL CSV不进入接口和仓库。

## 10. 校验方式

- Pydantic模型负责运行时字段、类型和默认值校验。
- JSON Schema负责跨语言端口契约。
- `tests/test_m2_final_contract.py`校验必填字段、版本、维度ID和五套样本。
- 运行时评分卡与契约评分卡必须逐字段一致。
