# M4-A 自然语言录入与草稿确认

- 模块：M4-A（M4 增量）
- 日期：2026-11-06
- 依赖：M0 契约、M1 模型、M2 统计内核、M3 会话/工具、M4 AgentRunner
- 范围：仅后端自然语言抽取、草稿追问、确认后接入现有评估链路
- 不包含：M5 页面、M6 完整安全过滤、M2 公式修改、数据库、RAG

## 1. 目标流程

```text
用户自然语言
-> 抽取模型返回结构化草稿
-> 后端合并草稿
-> 检查缺失字段
-> 缺失时追问
-> 用户补充后再次抽取
-> 信息完整后返回预览
-> 用户确认
-> 创建匿名内存会话
-> Agent 调用 run_risk_assessment
-> 返回 AssessmentResult 和 Explanation
```

自然语言原文只用于当前抽取请求，不写入 DraftStore；DraftStore 只保存结构化草稿、缺失字段、追问状态和 TTL。

## 2. 新增接口

```http
POST /api/v1/agent/intake
POST /api/v1/agent/intake/{conversation_id}/confirm
```

`/agent/intake` 返回：

- `needs_more_info`：信息不完整，返回 `missing_fields` 和 `reply`；
- `ready_for_confirmation`：信息完整，返回预览；
- `invalid`：解析失败或数值明显非法。

`/confirm` 只接受已完成草稿，重新执行 Pydantic 校验，然后复用：

```text
SessionStore -> AgentRunner -> ToolExecutor -> M2 -> Explanation
```

## 4. 内存草稿

`src/riskguard/services/draft_store.py`：

- 仅进程内存；
- 默认 TTL 30 分钟；
- 最多 3 轮补充；
- 不写数据库；
- 不写 localStorage；
- 不写日志；
- 确认评估或过期后删除。

## 5. 隐私边界

M4-A 为了完成自然语言抽取，用户当前轮原始文本会发送给专用抽取模型；该行为已纳入方案 A 的隐私口径。

约束：

- 原始文本不进入 `AssessmentRequest`；
- 原始文本不进入报告模型；
- 原始文本不写入 DraftStore、日志、数据库或 localStorage；
- 报告模型只接收 `AssessmentResult`；
- 用户必须确认结构化预览后才进入计算；
该隐私口径由项目负责人选择方案 A；正式公开演示前仍需要经济统计同学和项目负责人完成内容与隐私复核。

## 6. 验证

- M4-A 专项测试：`tests/test_agent_intake.py`
- 完整链路：自然语言 -> 抽取 -> 预览 -> 确认 -> `run_risk_assessment` -> Explanation
- 缺失信息：不创建正式会话、不调用 M2
- 多轮补充：按债务标签/索引合并，不覆盖已有非空字段
- 非法提取：返回 `invalid`，不调用 M2
- 非法 JSON：清洗代码围栏后解析，失败返回降级
- 隐私：报告 Prompt 不包含原始自然语言

## 8. 已结清负债与订阅补充规则

- `remaining_periods=0` 或用户明确说“已经还完/已结清”时，M4 草稿标记 `settled=true`；
- 已结清记录保留在预览中，但不会进入正式 `AssessmentRequest.debts`；
- 已结清记录不参与 DTI、IRR、评分和现金流；
- 会员、订阅、自动续费、连续包月、月费进入 `recurring_subscriptions`，不需要本金、期数和利率；
- 前端只展示大白话 `reply`，不展示内部字段名、JSON key 或数组下标。
