## 1. 目标

在保持金融教育边界和隐私约束的前提下，让多轮追问更接近普通大模型的连续性：

1. 首次用户输入不占追问轮数；
2. 首次输入后默认允许 8 轮补充；
3. 只保存最近有限消息，不保存完整聊天历史；
4. 追问不重复询问已知字段；
5. 达到上限后保留草稿并给出明确退路；
6. 不使用模型自身记忆，不引入 RAG、LangChain、CrewAI 或 AutoGen。

## 2. 轮数计数方案

```text
首次输入                 -> clarification_turns = 0
第 1 次补充并仍需信息     -> clarification_turns = 1
第 2 次补充并仍需信息     -> clarification_turns = 2
...
第 8 次补充并仍需信息     -> clarification_turns = 8
下一次补充               -> clarification_limit，不调用 LLM
```

- `MAX_CLARIFICATION_TURNS` 默认 8，允许范围 1-50；
- 只有返回 `needs_more_info` 的补充轮才消耗轮次；
- 解析失败、数值校验失败或信息完整时不额外消耗轮次；
- 第 9 次输入在进入抽取模型前被拦截；
- 达到上限不创建正式评估会话，不覆盖已有结构化草稿；
- 响应继续返回 `preview`，方便页面或结构化表单继续补充。

上限固定文案：

```text
我已经记录了你目前提供的信息。为了避免反复追问，你可以改用结构化表单继续补充，或者点击重新开始。
```

## 3. ChatMemoryStore 设计

文件：

```text
src/riskguard/models/memory.py
src/riskguard/services/chat_memory_store.py
```

`ChatMemoryState` 包含：

- `conversation_id`
- `messages`
- `last_intent`
- `last_topic`
- `last_assessment_id`
- `last_answer_type`
- `last_tool`
- `created_at`
- `expires_at`

`MemoryMessage` 只包含：

- `role`
- `content`
- `created_at`

配置：

| 环境变量 | 默认值 | 范围 | 说明 |
|---|---:|---:|---|
| `MAX_CLARIFICATION_TURNS` | 8 | 1-50 | 首次输入后最多补充轮数 |
| `CHAT_MEMORY_MAX_MESSAGES` | 8 | 1-10 | 每个 conversation 最多保留消息数 |
| `CHAT_MEMORY_TTL_SECONDS` | 1800 | 1-86400 | 短期记忆 TTL |

行为：

- 只存在进程内字典；
- 线程安全；
- 超过消息上限删除最旧消息；
- TTL 过期后读取、追加和主动清理都会移除状态；
- 删除 conversation 时同时删除 ChatMemoryStore、DraftStore 和 ConversationStore；
- 不写 SQLite、CSV、日志、文件、数据库或 localStorage。

## 4. 上下文发送范围

### 信息抽取

发送：

- 当前用户消息；
- 当前结构化 AssessmentDraft；
- 上一轮未回答的问题；
- ExtractionResult 和 AssessmentRequest Schema。

不发送完整聊天历史，不发送无界 `messages` 数组。

### 科普回答

发送：

- 当前用户问题；
- 当前选中的科普卡片；
- 当前主题；
- EducationAnswer Schema。

### 风险解释

只发送：

- `AssessmentResult`；
- Explanation Schema。

不发送当前消息、原始聊天、草稿或完整财务档案。

### 情景模拟

发送：

- 当前情景描述；
- 当前结构化会话状态；
- ScenarioExtractionResult Schema。

工具参数仍只包含 `session_id` 和 `scenario_id`。

## 5. 多轮追问行为

- “那再补一个”使用上一轮问题和当前结构化草稿理解指代；
- 已知字段不会再次询问；
- 用户明确纠正时，新值覆盖对应旧值；
- 新命名的债务或订阅追加到草稿，不覆盖无关记录；
- 已结清记录标记 `settled=true`，不进入正式 `AssessmentRequest.debts`；
- 会员、订阅、自动续费、连续包月和月费进入 `recurring_subscriptions`，不追问本金、期数或利率；
- 用户问“为什么我是中风险”时使用当前会话的 AssessmentResult，不从聊天文本猜数据；
- 用户问“如果新增一笔分期”时使用当前会话和情景模拟工具，不重新询问已有财务信息。

## 6. 页面行为

- 显示当前匿名 conversation ID；
- `needs_more_info` 显示已使用/最大轮数和剩余轮数；
- `ready_for_confirmation` 显示本次已使用补充轮数；
- `clarification_limit` 使用提示样式，不使用普通错误样式；
- 达到上限提供“重新开始对话”，并提示切换到结构化表单；
- 只显示后端友好 `reply`，不显示 `missing_fields` 原值；
- 清空界面状态时调用：

```http
DELETE /api/v1/agent/conversations/{conversation_id}
```

## 7. 隐私边界

允许：

- 原始消息短暂进入进程内 ChatMemoryStore；
- 当前轮必要文本发送给抽取、科普或情景模型。

禁止：

- 完整聊天历史发送给任何 LLM；
- 报告模型接收原始聊天或草稿；
- 聊天记忆写入认证 SQLite；
- 财务明细写入认证数据库；
- 日志中出现原始文本、金额、月供或利率；
- CSV、文件、数据库或 localStorage 保存聊天记录；
- 把用户原文写入 AssessmentRequest 或 AssessmentResult。

认证数据库继续只保存账号和认证会话；访客模式和登录模式共用相同聊天边界。
