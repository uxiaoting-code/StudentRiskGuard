# M5.7 向导式 Agent 页面

- 模块：M5.7
- 任务：M5.7-UI-01 一问一答向导；M5.7-UI-02 确认幂等；M5.7-UI-03 报告后追问
- 状态：代码完成，项目负责人页面手工验收通过；经济统计内容复核和真实 DeepSeek 联调仍 pending
- 依赖：M5 页面、M5.5 认证、M5.6 有界追问与短期上下文
- 范围：只调整页面交互和确认状态管理，不修改 M2 公式、认证数据库或 Agent 工具边界

## 1. 产品形式

将原来的“聊天 + 大表单”页面改为：

```text
自然语言描述或向导录入
-> 一次只问一个缺失字段
-> 结构化预览与用户确认
-> 调用 run_risk_assessment
-> 展示风险报告
-> 报告后继续对话追问、科普和情景模拟
```

页面仍然属于 Agent，因为后端继续使用：

```text
conversation_id
-> 当前结构化草稿
-> Agent 工具调用
-> M2 确定性计算
-> AssessmentResult
-> Explanation
-> 安全与 grounding 校验
```

## 2. 一问一答规则

- 首次输入不占追问轮数；
- 每轮只显示一个主要问题；
- `missing_fields` 仍完整返回给内部状态，但 `reply` 只显示当前最高优先级问题；
- 已知字段不重复询问；
- 用户纠正时覆盖对应旧值；
- 未知利率可明确标记为 unknown，不转换为 0；
- 达到追问上限后显示结构化表单或重新开始入口；
- 页面只显示友好 `reply`，不显示内部字段名。

## 3. 确认幂等

确认成功后草稿会从 DraftStore 删除。为避免浏览器双击、Streamlit rerun 或页面刷新导致重复确认：

- 前端增加 `confirming` 状态并禁用确认按钮；
- 确认成功后写入 `assessment_ready`、`session_id` 和 `last_agent_response`；
- 已生成报告时不再调用确认接口；
- 后端 `IntakeService.confirm()` 在 DraftStore 不存在时检查 ConversationState 的 session_id；
- 已有 session 时复用现有会话并返回评估结果；
- 没有 draft 且没有 session 时返回可恢复的 409 错误；
- 不把重复确认错误显示成“请新开一轮对话”的致命错误。

## 4. 页面状态

建议使用 Streamlit session_state 中的：

- `conversation_id`
- `session_id`
- `assessment_ready`
- `confirming`
- `last_chat_response`
- `last_agent_response`
- `last_user_message`
- `last_error`

状态只在页面进程内存中保存，不写入 localStorage、数据库、CSV 或日志。

## 5. 报告后追问

报告页下方继续提供对话输入，使用同一个 conversation_id：

- “为什么我是中风险？”复用当前 AssessmentResult；
- “什么是 IRR？”只使用教育卡片来源片段；
- “如果新增一笔分期会怎样？”使用当前 session 和情景模拟工具；
- “推荐一个借款平台”返回 out_of_scope，不推荐平台、不判断审批或额度。

## 6. 隐私边界

- 当前轮文本只发送给必要的抽取、科普或情景模型；
- 报告模型只接收 AssessmentResult；
- 不发送完整聊天历史或完整财务档案；
- 不把财务明细写入认证 SQLite；
- 删除会话时清理 ChatMemoryStore、DraftStore、ConversationStore、ScenarioStore 和 SessionStore；
- Demo 和测试只使用合成数据。

## 9. M5.7.1 多笔债务与订阅修复

- 多笔债务按当前债务的标签逐笔追问，例如“花呗这笔分期现在大概还欠多少钱？”
- 自动续费、会员、订阅、连续包月、月费进入 `recurring_subscriptions`，不进入正式 `debts`；
- 会员分期等歧义名称会先追问“一次性分期还是每月自动续费”；
- 草稿新增 `total_remaining_repayment`、`final_payment` 和 `derived_fields`；
- 剩余本金与总剩余还款额分开保存，不能把总还款额直接当成剩余本金；
- 当总还款额能被月供整除时，由 Python 推导剩余期数；
- 不能整除时追问最后一期金额，不进行四舍五入猜测；
- 用户明确提供的剩余期数不被系统覆盖；
- 预览中标记由系统推导的期数；
- 所有推导只发生在输入归一化层，不修改 M2 公式。
