# M5.7.2 口语化意图与多轮短句补全

- 模块：M5.7.2
- 日期：2026-11-09
- 依赖：M5.6 有界上下文、M5.7/M5.7.1 向导式录入、M6 安全边界
- 状态：代码与自动化验收完成，待真实公网手工复核

## 1. 问题背景

公网试用发现两类问题：

1. “我现在月收入2000，还有800的零花钱”“我一个月就三千”等正常收入描述被误判为借贷平台请求；
2. 上一问询问剩余欠款时，用户只回复“3000”，系统仍重复相同问题。

根因分别是口语化个人财务词覆盖不足、`out_of_scope` 关键词过宽，以及短句补充完全依赖 LLM 返回新草稿。

## 2. 意图路由

- 只有明确的平台推荐、借款可用性、审批、额度、通过率、放款、以贷养贷等请求才进入 `out_of_scope`；
- 用户描述“我借钱买了个手机”属于个人负债记录，应进入 `assessment_intake`；
- 月收入、工资、生活费、零花钱、爸妈给、兼职、奖学金等属于个人收支信号；
- 没有负债、没有分期、已经还完、已经结清属于个人数据信号；
- “月收入是什么意思”“兼职收入怎么算”等明确概念问题进入 `education`；
- 普通无法识别输入进入内部 `general_help`，返回帮助式追问，不再默认使用借贷拒绝文案；
- 存在草稿时，明确教育问题可以正常回答，且不会删除当前草稿和 pending 状态。

## 3. 确定性短句补全

新增 `pending_field` 和无进展计数：

- `pending_field` 保存上一问对应的结构化字段；
- 上一问询问剩余欠款，用户回复“3000/三千/3千/3000元/大概3000”时，由 Python 直接写入目标债务；
- 命中确定性补全时不调用 LLM；
- 支持“每月300，还剩一年”同时写入月供和12期；
- “利率不知道/不清楚/忘了”写入 `nominal_apr=null`、`nominal_apr_status=unknown`，不会写0；
- 多个数字无法判断含义时不猜测，仍交给抽取模型并要求澄清；
- 中文数字解析使用纯 Python，不增加第三方依赖。

## 4. 原价与未还比例

`DebtDraft` 新增：

- `original_amount`
- `remaining_ratio`

例如“买的6000，还剩一半没还”：

1. 记录原价6000；
2. 记录未还比例0.5；
3. Python 计算 `6000 × 0.5 = 3000`；
4. `derived_fields` 标记 `remaining_principal`；
5. 返回 `REMAINING_PRINCIPAL_ESTIMATED` warning；
6. 预览显示“欠款按购买价和未还比例估算”；
7. 不把6000直接当作剩余本金。

## 5. 无进展保护

- 每轮比较补充前后的结构化草稿；
- pending_field 和草稿都未变化时，不原样重复同一问题；
- 第一次无进展改为区分金额含义的恢复式追问；
- 连续无进展时提示使用结构化表单；
- 达到对话轮数上限时仍保留草稿和表单退路。

## 6. 多笔债务

- `current_debt_index` 对应原始 `draft.debts` 索引；
- `_collect_missing_fields()` 跳过已结清债务但保留原始索引；
- 已完成花呗后，下一问必须带“白条”等下一笔债务标签；
- 确定性补全只更新 pending_field 指向的债务；
- 用户明确纠正“本金是2500”时覆盖旧值，不覆盖其他债务。

## 7. Prompt 约束

抽取 Prompt 新增：

- 短数字必须映射到 previous_question 对应字段；
- 一年、半年、一年半分别转换为12、6、18期；
- 无法判断数字含义时返回 needs_more_info，不返回原草稿；
- 口语化收入不是借贷推荐；
- 无负债和已结清要更新草稿；
- 原价、剩余比例、剩余本金、总还款额严格区分；
- 模型不计算金融指标，推导由 Python 负责。

## 8. 隐私边界

- `pending_field`、原价、比例和无进展计数只保存在进程内 DraftStore；
- 原始文本仍只发送给当前轮抽取模型；
- 不发送完整聊天历史；
- 不写日志、数据库、CSV或localStorage；
- 报告解释模型仍只接收结构化 AssessmentResult；
- 删除 conversation 时清理草稿和上下文。
